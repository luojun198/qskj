### 4. 现有代码现状
- `importAcdSupplyChain.ts` 只导 **仓库 / 往来 / 物料**三类档案，并且只在「财务 ACD 新建账套」流程末尾被顺带调用；没有独立入口，不导单据、订单、库存、往来。

- 开发库 `finance-0523.db` 中**没有**嘉之通账套，验证前需先用其财务 ACD 建账，或指定一个测试账套。

## 二、总体方案

**独立入口、导入到当前账套、只写进销存表、可预检、可整体回滚。**

```
上传 .acd ──► ① 解析 + 识别（确认是进销存库，不是财务库）
          ──► ② 预检报告（不落库）：各类数量、映射缺口、编码冲突、科目缺失、日期区间
          ──► ③ 主人确认选项 ──► ④ 事务内导入 ──► ⑤ 与 kcb / hzk / wldj 自动核对 ──► 导入报告
```

### 核心原则
1. **目标账套必须已存在**（通常已先导入同一客户的财务 ACD），只写 `scm_*` 表。
2. **按单据日期顺序逐张走本系统审核逻辑**生成库存流水、成本、往来，保证导入后与手工录入的单据行为完全一致（可反审核、可下推、可生成凭证）。
3. 导入前**自动备份单账套**（复用 FIX-329 的单账套备份）；导入失败整体回滚，导入成功也可「一键撤销本次导入」。
4. 所有导入记录带 `acd_raw` 与导入批次号 `import_batch_id`，便于追溯和撤销。
5. 不生成凭证：财务账套里已有对应凭证，导入的单据统一标记「已在原系统制证」，避免业务凭证中心重复生成。

## 四（原）、需要主人确认的问题

1. **「3 成品入库」怎么映射？** 共 288 张，往来单位都是 `999999`，本系统没有对应的生产计划。可选：
   - a. 映射为「其他入库 OI（类别：成品入库）」——最稳，不依赖生产计划（**推荐**）；
   - b. 映射为「完工入库 PF」——需要虚拟生产计划，复杂且语义不准；
   - c. 如果实际是外购成品，映射为「采购入库 PI」。
2. **单据状态**：润衡里 `bz_sh`（审核标志）几乎全是 0，但已影响库存。是否全部按「已审核」导入？（推荐是，否则库存对不上）
3. **出库成本以谁为准**：本系统按当前计价方式重算，还是强制沿用润衡记录的单位成本 `dwcb`？（推荐重算并出差异报告；若客户财务凭证已按润衡成本记账，则需沿用润衡成本）
4. **凭证**：导入的单据是否一律标记「已制证、不再生成凭证」？（推荐是，财务账套里已有对应凭证）
5. **目标账套**：嘉之通财务账套是否已在客户环境导入？开发库里没有，验证时我需要一份嘉之通的**财务 ACD**，或者先用空白测试账套验证。
6. **重复导入**：同一客户以后再给新的进销存备份（如月底再导一次），是否需要「增量导入」（只导新单据）？还是每次清空进销存后全量重导？（第一期建议只做全量 + 撤销）

## 五、风险

| 风险 | 应对 |
|---|---|
| 润衡其他版本列顺序不同 | 一律按 `data_stru` 列名取值，缺列报告 |

| 大文件阻塞服务 | 后台任务 + 分批事务，参照 FIX-333 |
| 档案编码与已有数据冲突 | 预检列出，三种冲突策略可选 |
