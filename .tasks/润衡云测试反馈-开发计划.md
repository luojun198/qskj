## 二、开发任务拆分

### 阶段 1（P0）：含税口径统一 + 订单去凭证 + 委外用料打通，预计 2~3 天

**T1 进销存单据默认显示含税列**
- 采购、销售类单据（PQ/PO/PI/PR/RP、SQ/SOa/SO/SR/RS）在默认明细列中加入：含税单价、税率%、税额、价税合计。
- 已配置过 `line_fields` 的账套用迁移补齐这几列（只补不删）；用户仍可在列方案中隐藏。
- 合计行增加「税额合计」和「价税合计」；表头右上角的「合计金额」改为显示价税合计，并注明不含税金额。
- 文件：`client/src/views/scm/DocForm.vue`（`lineCols`）、`server/src/routes/scmDoc.ts`（默认类型配置），新增迁移。

**T2 金额口径核对（订单 → 入库/出库 → 往来 → 收付款）**
- 往来余额表、应收应付明细的「发生额」继续用含税金额；点开单据后能看到同一个价税合计，两边一致。
- 收付款单从源单带入金额时一律取价税合计，查看现有逻辑是否有取不含税金额的地方。
- 补充单元测试：同一组 PO→PI→应付→付款，四处金额完全一致。

**T3 订单类单据去掉「生成凭证」**
- 前端：`DocForm.vue` 顶部按钮、`ScmDocActions.vue` 列表的「凭」按钮、`DocList` 批量生成凭证，都排除 `dir='none'` 的订单、报价、询价类单据。
- 后端：生成凭证接口对这类单据直接拒绝（防止绕过前端调用）；「业务凭证」管理中心的待生成列表同样排除。

**T4 委外/生产计划用料带出**
- BOM 编辑页：组件行默认是「主件」；保存时若整张 BOM 没有任何主件，给出明确提示（「全部为副产品，计划将没有用料」）。
- 计划由客户订单或 MRP 下推生成时，自动带出成品的默认 BOM（复用 `ProductionPlanForm` 的 `pickDefaultProductBom`）。
- 工单「用料汇总为空」的提示改得更具体：区分「未指定 BOM」和「BOM 中没有主件」两种情况。

**T5 委外发料修复**
- 提示条：没有计划数据时不显示，有数据时补全数值。
- 来源工单没有用料时，在页面上明确说明原因并提供跳转按钮「去编辑计划/BOM」，不再出现空白表格。
- 回归测试：建 BOM → 建委外计划 → 审核 → 发料 → 收货，走通全流程。

### 阶段 2（P1）：核销单管理 + 库存查询 + 列表审核，预计 2~3 天

**T6 核销单列表（全页面，参照金蝶「核销单记录」）**
- 新路由 `/scm/arap/verify-records`：按日期、往来单位、业务类型（预收冲应收、预付冲应付、应收冲应付等）、单号筛选。
- 列表列：单据日期、核销单号、业务类型、客户/供应商、核销金额、制单人、备注、生成方式（手动/自动）。
- 支持查看明细、删除（即取消核销，批量操作需逐张确认）、导出。
- 核销详情页：上下两张表（收付款一侧 / 应收应付一侧），列出源单金额、已核销、未核销、本次核销金额；页面结构参照金蝶截图。
- 后端：在现有 `/scm/arap/verify-list` 的基础上增加跨单位分页查询和业务类型字段。

**T7 往来核销页显示已核销的预收/预付**
- 右侧增加「显示已核销完毕」开关，余额为 0 的收付款以灰色显示并标注对应的核销单号，可点击跳转。
- 页面顶部的「核销记录」入口改为跳转到 T6 的列表页。

**T8 库存查询增加导出和打印**
- `StockList.vue` 增加「导出 Excel」和「打印」按钮，按当前筛选条件和列设置输出（复用现有的列表导出/打印工具）。

**T9 计划列表增加审核（下达）**
- `ProductionPlan.vue`（委外计划共用这个页面）勾选后可批量「审核」，和已有的「反审核」并列。
- 逐个检查进销存、委外、装配各类单据列表，确认都能在列表上审核和反审核，补上缺失的入口。

### 阶段 3（P2）：列表增强，预计 1 天

**T10 订单列表显示关联下游单号**
- 采购订单列表增加「关联入库单号」列，销售订单列表增加「关联出库单号」「关联收款单号」列，单元格内多行显示，点击可跳转。
- 后端基于 `scmDocLineage` 聚合下游单号，注意十万级数据量下的性能（只查当前页的单据 ID）。

### 装配单据

- 客户把它列在完善范围内，但本次文档没有给出具体问题。建议在阶段 1 结束后自测一轮装配/拆卸单：含税口径、列表审核、凭证、成本，问题并入 T2 和 T9 一起修。

## 实施计划

### 第一批（P0，约 1.5 天）：显示错乱与报错
1. **M1 凭证管理列表错乱**
   - 先在本地复现：筛选 / 刷新 / 切换期间后旧行残留，同时出现空状态图。
   - 修复思路：数据重置时让虚拟表格重新挂载或滚回顶部；空状态只在确无数据时显示；单元格改为单行省略（复用凭证录入列表的 `vt-cell-text`）。
   - 同步：审核页、查询页统一换成凭证录入列表的简洁样式（白底、细线、微软雅黑、凭证级列合并显示）。
2. **M2 / M3② 来源数量超限提示与下推后保存报错**
   - 提示改成人能看懂的写法，例如：「物料 0101：来源订单 202610-SOa-001 数量 100，允许超收 20% 即上限 120；已被出库单占用 100（其中草稿 202610-SO-001 100，请先审核或删除）；本次 100，合计 200 超出上限。」
   - 排查下推生成草稿后再保存时，是否把本单 / 同源草稿重复计入占用，修正排除逻辑。
3. **M3① 选源单弹窗只显示 2 行**：弹窗打开后重新布局（或改为固定高度、不用 max-height），保证明细一次显示完整。

### 第二批（P1，约 3～4 天）：订单变更单 + 小优化
4. **M4 采购 / 销售订单变更单**（全页面，参照工单变更单）
   - 新表 `scm_order_change`：保存变更前后快照与差异，状态为草稿 / 已审核，带变更原因、经办人。
   - 可变更：
     - 数量增加 / 减少，不得低于已入库（或已出库）数量。
     - 单价只对未执行部分生效，已生成的下游单据保持原价。
     - 新增 / 删除明细，已执行的行不能删除。

**5. Q7 发票选源单**（主人要求：一张发票可以对应多张源单；同一张源单也可以分几张发票开）
现有发票账务按表头**单一** `source_doc_id` 整单「以发票为准」：`applyInvoice`（`scmArAp.ts:190`）把来源单的台账金额整笔改成发票额；`reverseInvoice`（:239）按来源单全部行还原；发票制证（`scmDoc.ts:4861` / `5057`）把**未被引用的来源行当作开票额 0** 冲掉。多源、分批开票时这三处都会算错，必须改成**按行计差额**：
- **账务口径**：发票每一行，有 `source_line_id` 的，差额 = 发票行价税 − 来源行价税（按开票数量折算的部分：来源行金额 × 开票数量 / 来源数量）；没有源行的，按发票行全额新挂往来。未开票的来源行**保持暂估**，不再冲为 0，等下一张发票。
- **新表（迁移 162）`scm_invoice_arap_adjust`**：invoice_id、src_doc_id、src_log_id、delta_fc、delta_base。`applyInvoice` 按来源单分组，把差额累加到各来源单的 in 台账（amount += delta），每笔写一条调整记录；校验调整后金额 ≥ 已核销金额。`reverseInvoice` 按调整记录逐笔回减，删掉调整记录；无源部分照旧删除自己的台账。表头 `source_doc_id` 改为只作展示（取第一张），账务一律走行级。
- **旧数据兼容**：已审核的旧发票（有表头 `source_doc_id`、没有调整记录）反审核时走原来的整单还原逻辑。迁移不改历史数据。
- **发票制证**：差额分录按「已引用的行」逐行计算，去掉「未引用的来源行按 0 计」；无源行按普通发票全额制证（借存货 / 进项、贷应付，销售对称）。前置校验改为：引用到的**每一张**来源单都已生成凭证，否则逐一列出单号。
