# 往来余额表改为「按往来单位汇总总余额」

## 问题诊断

- `/scm/arap` 菜单叫"**往来余额表**"，但实际行为是**逐笔流水明细**（每行一张单据：日期/单据类型/单号/发生额），不是用户期望的"往来单位的总余额"
- 系统已有独立的 `/scm/arap-detail`（**往来明细账**）路由，复用同一个 `PartnerLedger.vue`——"逐笔明细"的职责已有专属入口
- 后端 `getAllPartnerLedger`（`scmArAp.ts:177`）返回逐笔行，但内部已算 `openingMap`（按 partner 的期初），可直接复用做汇总
- 用户确认：**统一净额·四列**（期初余额/本期增加/本期减少/期末余额），配合顶部"应收/应付/全部"筛选

## 分工（两个菜单各司其职）

| 菜单 | 路由 | 行为 |
|---|---|---|
| **往来余额表** | `/scm/arap` | **改为：按往来单位汇总，一行一单位**（期初/增加/减少/期末） |
| 往来明细账 | `/scm/arap-detail` | 保持逐笔明细不变（已是这个职责） |

## 改动范围（2 后端 + 2 前端）

### 1) 后端 `server/src/services/scmArAp.ts` — 新增 `getPartnerBalanceSummary`

在 `getAllPartnerLedger`（:177）之后新增汇总函数（完全复用现有期初 SQL 思路 + 本期增减聚合）：

```ts
/** 往来余额表：按往来单位汇总（期初/本期增加/本期减少/期末）。净额口径，配合 arapType 筛选。 */
export function getPartnerBalanceSummary(db, accountSetId, startDate?, endDate?, arapType?) {
  // 期初（startDate 之前净额，按 partner_code 聚合）；无 startDate 则期初=0
  const openingMap = new Map<string, number>()
  if (startDate) {
    const arapOb = arapDocTypeCond(arapType)
    const obs = db.prepare(`SELECT partner_code,
        COALESCE(SUM(CASE WHEN direction='in' THEN amount ELSE -amount END),0) bal
      FROM scm_ar_ap_log WHERE account_set_id=? AND doc_date<?${arapOb.sql ? ' AND ' + arapOb.sql : ''}
      GROUP BY partner_code`).all(accountSetId, startDate, ...arapOb.params)
    for (const o of obs) openingMap.set(o.partner_code, o.bal || 0)
  }
  // 本期发生：按 partner_code 聚合 in/out
  const arapMain = arapDocTypeCond(arapType)
  const conds = ['account_set_id=?']; const ps = [accountSetId]
  if (startDate) { conds.push('doc_date>=?'); ps.push(startDate) }
  if (endDate)   { conds.push('doc_date<=?'); ps.push(endDate) }
  if (arapMain.sql) { conds.push(arapMain.sql); ps.push(...arapMain.params) }
  const rows = db.prepare(`SELECT partner_code,
      COALESCE(SUM(CASE WHEN direction='in'  THEN amount ELSE 0 END),0) AS period_in,
      COALESCE(SUM(CASE WHEN direction='out' THEN amount ELSE 0 END),0) AS period_out
    FROM scm_ar_ap_log WHERE ${conds.join(' AND ')} GROUP BY partner_code`).all(...ps)
  // 合并期初+本期，挂 partner 名称/类型；保留无发生但有期初的单位
  const codes = new Set([...openingMap.keys(), ...rows.map((r:any)=>r.partner_code)])
  const r2 = (n:number)=>Math.round(n*100)/100
  const summary = [...codes].map(code => {
    const r:any = rows.find((x:any)=>x.partner_code===code) || { period_in:0, period_out:0 }
    const opening = openingMap.get(code) || 0
    const periodIn = Number(r.period_in) || 0
    const periodOut = Number(r.period_out) || 0
    const closing = opening + periodIn - periodOut
    return { partner_code: code, opening:r2(opening), period_in:r2(periodIn), period_out:r2(periodOut), closing:r2(closing) }
  }).filter(e => Math.abs(e.opening) + Math.abs(e.period_in) + Math.abs(e.period_out) > 0.005)
  // 挂 partner 名称/类型
  if (summary.length) {
    const names = db.prepare(`SELECT code,name,partner_type FROM scm_partner WHERE account_set_id=? AND code IN (${summary.map(()=>'?').join(',')})`).all(accountSetId, ...summary.map(s=>s.partner_code))
    const nm = new Map(names.map((n:any)=>[n.code, n]))
    for (const s of summary) { s.partner_name = nm.get(s.partner_code)?.name || null; s.partner_type = nm.get(s.partner_code)?.partner_type || null }
  }
  return {
    summary,
    total_opening: r2(summary.reduce((s,e)=>s+e.opening,0)),
    total_in:      r2(summary.reduce((s,e)=>s+e.period_in,0)),
    total_out:     r2(summary.reduce((s,e)=>s+e.period_out,0)),
    total_closing: r2(summary.reduce((s,e)=>s+e.closing,0)),
  }
}
```

> 口径完全对齐现有 `getAllPartnerLedger`：`direction='in'` 算增加、`'out'` 算减少；`arapDocTypeCond` 同款筛选；数值 `r2` 两位小数。

### 2) 后端 `server/src/routes/scmDoc.ts` — 新增路由

**关键：路由顺序**。Express 按定义顺序匹配，现有 `/scm/arap/:partnerCode`（:2391）会贪婪匹配 `/scm/arap/balance-summary`，所以新路由**必须定义在 `/scm/arap/:partnerCode` 之前**。最稳妥放在 `/scm/arap`（:2344）紧后面：

```ts
import { ..., getPartnerBalanceSummary } from '../services/scmArAp.js'  // 顶部 import 补此项

router.get('/scm/arap/balance-summary', (req: AuthRequest, res) => {
  const db = getDb(); const aid = asid(req)
  const { start_date, end_date, arap_type } = req.query as any
  res.json({ code: 0, data: getPartnerBalanceSummary(db, aid, start_date, end_date, arap_type) })
})
```

> 用独立路径，**不动**现有 `/scm/arap`（明细账和现有逐笔视图还在用），避免破坏。

### 4) 前端 `client/src/views/scm/PartnerLedger.vue` — 余额表模式改为汇总视图

**核心思路**：用 `isDetailPage`（已存在 :88）区分两种模式：
- `isDetailPage === false`（即 `/scm/arap` 余额表）且未选 partner → **显示汇总表**（一行一单位）
- `isDetailPage === true`（即 `/scm/arap-detail` 明细账）→ 保持现有逐笔明细不变
- 任一模式选了 partner → 复用现有单单位明细（`getPartnerLedger`）

具体改动：
- **新增数据 refs**：`summary` / `totalOpening` / `totalIn` / `totalOut` / `totalClosing`
- **新增 computed `isSummaryView`**：`= !isDetailPage.value && !partnerCode.value`（余额表 + 未选单位 = 显示汇总）
- **`load()` 分流**：`isSummaryView` 时调 `getPartnerBalanceSummary` 填汇总数据；其它分支不变
- **模板**：新增 `v-if="isSummaryView"` 的汇总表：
  - 列：`#` / 往来单位 / 类型(客户/供应商/客户+供应商 tag) / 期初余额 / 本期增加 / 本期减少 / 期末余额 / 操作(查看明细)
  - 双击行 → 下钻（复用 `drillPartner` :132，自动设 partnerCode 切到单单位明细）
  - `show-summary` 显示合计行（`total_opening/in/out/closing`）
- **顶部合计提示**：余额表模式显示 `期初合计 X / 增加合计 Y / 减少合计 Z / 期末合计 W`
- 明细账模式（`isDetailPage`）的模板和逻辑**完全不动**

## 不改动的部分

- `/scm/arap-detail`（往来明细账）：保持逐笔明细，逻辑不变
- `/scm/arap/:partnerCode`（单往来明细，下钻用）：不变
