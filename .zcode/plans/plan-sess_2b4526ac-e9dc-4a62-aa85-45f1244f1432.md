## 修改目标

完善 SCM 单据列表页(`/scm/docs`)的筛选区:
1. **往来单位**从纯文本输入改为**下拉框**,数据源是「按当前账套实际发生过单据的往来单位」(`DISTINCT partner_code, partner_name FROM scm_doc`)
2. **新增筛选项**:状态(草稿/已审核)、业务员、单据号/备注关键字
3. **日期范围合并**为单个 `el-date-picker type="daterange"`
4. **筛选项按单据类型动态显示**(根据当前 `filters.doc_type` 决定往来单位/业务员是否显示——比如调拨单无往来单位)
5. **新增「重置」按钮**
6. 保持单行布局

## 现状

`client/src/views/scm/DocList.vue` 第 4-63 行筛选区,5 个控件:
- 单据类型 `el-select`、仓库 `el-select`、往来单位 `el-input`(纯文本,要求输编码)、开始日期 `el-date-picker`、结束日期 `el-date-picker`
- 后端 `/api/scm/docs`(`server/src/routes/scmDoc.ts:629-650`)支持 `doc_type/partner_code/warehouse_code/status/start_date/end_date/payment_mode`,其中 `partner_code` 精确等于、`status` 后端支持但前端无控件

## 修改方案

### 一、后端(2 个文件)

**1. `server/src/routes/scmDoc.ts`**

a. **新增 GET `/scm/docs/partner-options`**(在 `/scm/docs/ids` 之前注册,避免被动态路由吞):
```sql
SELECT DISTINCT d.partner_code, p.name AS partner_name
FROM scm_doc d LEFT JOIN scm_partner p ON p.account_set_id=d.account_set_id AND p.code=d.partner_code
WHERE d.account_set_id=? AND d.partner_code IS NOT NULL AND d.partner_code != ''
  [AND d.doc_type=?]  -- 可选:传 doc_type 时只返回该类型下出现过的
ORDER BY partner_name
```
返回 `[{ partner_code, partner_name }]`。让下拉只列"真实有过业务的单位",而非全部档案。

b. **新增 GET `/scm/docs/biz-person-options`**(业务员 DISTINCT):
```sql
SELECT DISTINCT biz_person FROM scm_doc
WHERE account_set_id=? AND biz_person IS NOT NULL AND biz_person != ''
  [AND d.doc_type=?]
ORDER BY biz_person
```
返回 `[{ biz_person }]`。

c. **`/scm/docs` 与 `/scm/docs/ids` 增加 `keyword`、`biz_person` 参数**:
```ts
if (keyword)    { conds.push('(d.doc_no LIKE ? OR d.remark LIKE ?)'); const k = `%${keyword}%`; ps.push(k, k) }
if (biz_person) { conds.push('d.biz_person=?'); ps.push(biz_person) }
```
两处路由都加(`/scm/docs` 和 `/scm/docs/ids` 翻页要一致)。

**2. `client/src/api/scm.ts`** 补两个方法:
```ts
getDocPartnerOptions: (params?: { doc_type?: string }) => request.get('/scm/docs/partner-options', { params })
getDocBizPersonOptions: (params?: { doc_type?: string }) => request.get('/scm/docs/biz-person-options', { params })
```
`getDocs` 的 params 类型加 `keyword?: string; biz_person?: string`。

### 二、前端(`client/src/views/scm/DocList.vue`)

**1. filters reactive 扩展字段**:
```ts
const filters = reactive({
  doc_type: ...,
  warehouse_code: ...,
  partner_code: ...,
  biz_person: '',       // 新增
  status: ...,          // 已有但无控件,补控件
  keyword: '',          // 新增(单据号/备注)
  date_range: [] as string[],  // 新增,合并 [start_date, end_date]
  // start_date / end_date 改为 computed 派生自 date_range
})
```
保留 `start_date`/`end_date` 作为 computed(从 `date_range[0]/[1]` 派生),供 load() 用,避免改太多下游。

**2. 筛选项按单据类型动态显示**(复用 DocForm 的 `headerCols` 思路):
```ts
// 当前类型是否涉及往来单位/业务员(根据 SCM_DOC_TYPES 配置 + 兜底)
const showPartnerFilter = computed(() => {
  if (!filters.doc_type) return true  // 全部类型时显示
  const t = DOC_TYPES.find(d => d.code === filters.doc_type)
  return t?.header?.includes('partner') ?? true  // 配置里有 partner 才显示
})
const showBizPersonFilter = computed(() => {
  if (!filters.doc_type) return true
  const t = DOC_TYPES.find(d => d.code === filters.doc_type)
  return t?.header?.includes('biz_person') ?? false
})
```
往来单位/业务员下拉控件 `v-if="showPartnerFilter"` / `v-if="showBizPersonFilter"`。

**3. 模板改造**(单行 + 重置):
```html
<div class="filter-row">
  <el-select v-if="!propType" v-model="filters.doc_type" ...>...</el-select>
  <el-input v-model="filters.keyword" placeholder="单据号/备注" clearable style="width:160px" size="small" @keyup.enter="reloadFromFirstPage" />
  <el-select v-if="showPartnerFilter" v-model="filters.partner_code" filterable clearable placeholder="往来单位" style="width:200px" size="small" :loading="partnerLoading">
    <el-option v-for="p in partnerOptions" :key="p.partner_code" :label="`${p.partner_code} ${p.partner_name || ''}`" :value="p.partner_code" />
  </el-select>
  <el-select v-model="filters.warehouse_code" ...>...</el-select>
  <el-select v-if="showBizPersonFilter" v-model="filters.biz_person" filterable clearable placeholder="业务员" style="width:120px" size="small">
    <el-option v-for="b in bizPersonOptions" :key="b.biz_person" :label="b.biz_person" :value="b.biz_person" />
  </el-select>
  <el-select v-model="filters.status" placeholder="状态" clearable style="width:100px" size="small">
    <el-option label="草稿" value="draft" />
    <el-option label="已审核" value="audited" />
  </el-select>
  <el-date-picker v-model="filters.date_range" type="daterange" value-format="YYYY-MM-DD" start-placeholder="开始" end-placeholder="结束" style="width:240px" size="small" />
  <el-button type="primary" plain @click="reloadFromFirstPage" size="small">查询</el-button>
  <el-button size="small" @click="resetFilters">重置</el-button>
  <el-button type="primary" size="small" @click="handleCreate">新增</el-button>
  <!-- ...原有其他按钮 -->
</div>
```

**4. 下拉数据加载**:
- `onMounted` 调 `scmApi.getDocPartnerOptions()` 和 `scmApi.getDocBizPersonOptions()` 缓存全量(无 doc_type 参数)
- `watch(filters.doc_type)` 当类型变化时,重新拉取对应的 partner/biz-person options(限定在该类型下出现过)
- 用 `partnerOptions`/`bizPersonOptions` ref 存结果

**5. resetFilters 函数**:
```ts
function resetFilters() {
  filters.doc_type = propType.value  // propType 锁定时不可清
  filters.warehouse_code = ''
  filters.partner_code = ''
  filters.biz_person = ''
  filters.status = ''
  filters.keyword = ''
  filters.date_range = []
  reloadFromFirstPage()
}
```

### 三、不修改的内容

- `/scm/docs/ids` 翻页路由只在它本身的 WHERE 增补 keyword/biz_person,保持与列表一致(详情页翻页功能不破坏)
- 批量操作、列设置、tab 切换等原有功能不动
- 索引暂不加(数据量不大时无瓶颈,后续如需可补 `idx_scm_doc_partner`)
- 不引入 SalesFilterGroup 高级条件树(本次范围是基础多条件 AND,用户已确认单行布局足够)
