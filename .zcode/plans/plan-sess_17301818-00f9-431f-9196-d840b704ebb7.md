## 需求
把「往来管理」菜单中现有的两个直接打开表单的菜单项：
- `新增预收款单` → `/scm/docs/new?doc_type=RCV&payment_mode=advance`
- `新增预付款单` → `/scm/docs/new?doc_type=PAY&payment_mode=advance`

改为「列表页」入口，放到「应收应付账龄」后面。列表里带「新增」按钮（参照收款单列表 `/scm/docs?doc_type=RCV` 的实现）。

## 关键设计判断
后端**没有**持久化的"是否预付"标记字段，预收/预付款单与普通收付款单同表存储，唯一区别是：**该单据所有明细行的 `arap_source_log_id` 都为 NULL**（即未关联任何应收/应付源单）。采用**纯查询推导方案（无需数据库迁移）**，与现有数据模型一致。

## 实施步骤

### 1. 后端：列表查询支持预付过滤（`server/src/routes/scmDoc.ts`）
- `GET /scm/docs` 与 `GET /scm/docs/ids`：增加 `payment_mode` query 参数。
  - `payment_mode=advance`：只返回「全部明细行 `arap_source_log_id IS NULL` 且有明细行」的单据（用 `NOT EXISTS` 子查询过滤）。
- `queryDocRows` 的 SELECT 增加派生字段 `is_advance`（`CASE WHEN 明细行存在 AND 无任一行有 arap_source_log_id THEN 1 ELSE 0 END`），供前端展示。
- 利用已有索引 `idx_scm_doc_line_arap_source` 与 `idx_scm_doc_line_doc`，性能可接受。

### 2. 前端 API（`client/src/api/scm.ts`）
- `getDocs` / `getDocIds` 的 params 类型增加可选 `payment_mode?: 'advance'`。

### 3. 列表页（`client/src/views/scm/DocList.vue`）
- 读取 query 参数 `payment_mode`（同 `propType` 模式）。
- 「新增单据」按钮：当 `payment_mode=advance` 时，跳转 `ScmDocNew` 时携带 `query: { doc_type, payment_mode: 'advance' }`。
- 将列表过滤条件 `payment_mode` 透传给后端查询。
- 页面标题/类型名：当 `payment_mode=advance` 且 `doc_type=RCV` 显示「预收款单」，`PAY` 显示「预付款单」。

### 4. 导航菜单（`client/src/config/navigation.ts`）
- 删除现有的两个「新增预收/预付款单」菜单项（行 308-309）。
- 在「应收应付账龄」（行 313）后面新增两个列表入口：
  - `{ path: '/scm/docs?doc_type=RCV&payment_mode=advance', title: '预收款单', permission: 'scm:arap' }`
  - `{ path: '/scm/docs?doc_type=PAY&payment_mode=advance', title: '预付款单', permission: 'scm:arap' }`
- 路由权限：`/scm/docs` 已在 `ROUTE_PERMISSION_MAP` 放行（含 `scm:arap`），无需改权限映射。

### 5. 标签页标题（`client/src/views/Layout.vue` 的 `resolveTabTitle`）
- 增加：当 `r.path === '/scm/docs' && payment_mode==='advance' && dt==='RCV'` → 「预收款单」；`PAY` → 「预付款单」。

### 6. 测试
- 前端单元测试：`client/src/config/__tests__/navigation.spec.ts` 更新对应菜单项断言。
