# 税控·发票·一键报税集成可行性分析报告

> 面向对象：代理记账公司
> 分析时间：2026-09-05
> 结论：**整体可行，分三阶段实施。发票→凭证自动生成（高可行、高价值、可先行落地）；报税需"自动出数 + 人工确认提交"为主、第三方对接为辅；不建议自研直连电子税务局。**

---

## 一、系统现状盘点（已具备的基础）

| 能力 | 现状 | 是否利于本次需求 |
|---|---|---|
| 多账套 | `account_sets` 表，数据按 `account_set_id` 全量隔离，一个账套对应一家客户 | ✅ 天然适配代账公司"一客户一账套" |
| 模块授权 | `licenseModules.ts`：gl/cashier/asset/scm/production/outsource，注册码 v2 按 `mods` 授权 | ✅ 可新增「发票」「报税」模块 key，纳入授权 |
| 凭证引擎 | 录入/审核/过账/查询/打印/模板；`genVoucherHandler` 已实现按单据自动生成凭证 | ✅ 发票→凭证可直接复用 |
| 发票单据 | SCM 已有 `RP`(采购发票)/`RS`(销售发票) 单据，含 `invoice_no/invoice_type/invoice_date` 字段 | ⚠️ 仅手工登记，未接税控/数电数据 |
| 进销项税科目 | 系统参数 `scm:acc_tax_input`/`scm:acc_tax_output`（进项/销项税科目）可配置 | ✅ 凭证税科目录入已就绪 |
| 税相关凭证 | `scmDoc.ts:3527-3539` 已生成"借存货+进项税/贷应付"、"借应收/贷收入+销项税" | ✅ 发票自动制证逻辑已存在 |
| 报表系统 | 标准报表（资产负债表/利润表/现金流量表）+ 动态报表模板引擎（`reportTemplateExecutor` 公式取数） | ✅ 可据此生成纳税申报表 |
| 数据导入 | ACD 导入（润衡/用友账套）、Excel 导入、标准报表导入 | ✅ 可复用导入管线做发票导入 |
| 部署模式 | 私有化部署（机器码激活、`.bat` 启动、自带 node、SQLite） | ⚠️ 决定税控接入方式（见下） |

**关键结论：系统已具备"凭证引擎 + 税科目 + 报表取数引擎"，缺的是「发票数据入口」「发票到凭证的映射规则」「纳税申报表定义」「报税提交链路」。**

## 二、税控/发票数据接入（难点所在）

### 2.1 2026 年中国发票与税控环境

- **数电票（全电发票）已全国落地**，税控盘/税务UKey 逐步淘汰，主流对接方式为：
  1. **乐企直连**（税务官方直连，需资质：纳税信用 A/B、软著/使用权证明、固定 IP 备案，审批 30–60 天）——面向大型集团；
  2. **第三方财税 SaaS API**（百望云、用友税务云、票易云、企享云、云账房等）——面向中小微与代账，7–15 天上线，按年付费；
  3. **文件/OCR/接口导入**——Excel/OFD/PDF/邮件/数电下载，无需资质。
- **电子税务局申报**：目前**无全网公开的官方开放申报 API**。所谓"API 对接"多为第三方平台（登录电子税务局后封装操作）或特定省市试点/乐企能力。自研直连需逐省申请、签章、OAuth、频繁适配升级，**合规与维护成本极高**。

### 2.2 对代账公司的现实约束

- **每客户 = 一个纳税人**：各自税号（`nsrsbh`）、数电授权、服务商 APPID、报税登录凭证。系统需要「账套 ↔ 纳税人」绑定表。
- **私有化 + SQLite 部署**：接第三方云 API 技术上可行（HTTPS REST），但每客户需配置服务商凭证、且要考虑网络、外网访问与数据出域合规。
- **进项与销项分开**：
  - 进项：增值税发票综合服务平台勾选认证 + 数电票下载/OCR → 归集 → 生成进项/应付凭证。
  - 销项：乐企直连/第三方开票 → 系统读回开票结果 → 生成收入/应收凭证。
- **发票→凭证的核心难点**（非识别率，而是**映射与例外**）：
  - 发票购销方税号 → 系统往来单位（客户/供应商）自动匹配；
  - 税收分类编码/商品名 → 存货科目、收入/成本科目映射；
  - 专票可抵进项、普票不可抵；价税分离；
  - 红冲/作废/部分抵扣的处理；
  - 重复票、验真失败、映射缺失的**异常队列**。

## 三、各子项可行性评级

### 3.1 发票→凭证自动生成 —— 可行性：**高** ⭐⭐⭐⭐⭐
- 凭证引擎与税科目逻辑已存在（`scmDoc.ts` genVoucherHandler）。
- 需新增：发票主/明细表、发票导入/同步接口、税号→往来单位匹配、税收编码→科目映射、凭证生成（先草稿后过账）、异常队列。
- 建议：优先落地，价值高、风险低、可增量验证。

### 3.2 纳税申报表自动出数 —— 可行性：**高** ⭐⭐⭐⭐⭐
- 复用 `reportTemplateExecutor` 公式取数，从账上余额/发生额取数生成增值税申报表、附加税、企业所得税预缴表等。
- 进项/销项税在账上已归集（应交增值税明细），申报表数据可勾稽。
- 需新增：各税种申报表模板、取数与勾稽校验、申报数据预览。

### 3.3 一键报税（真正提交到税务局）—— 可行性：**中** ⭐⭐⭐
- **自动出数 + 导出/预填 + 人工确认提交**：最稳妥、合规、低风险，可立即落地。
- **对接第三方报税 SaaS**（百望云/用友/税友/云账房等）：可实现批量申报，但需客户授权、按省/税号配置、付服务费，且有账号/凭证外泄与责任归属问题。
- **自研直连电子税务局**：不推荐（资质、合规、维护、各省差异、风险高）。

### 3.4 代账批量工作流 —— 可行性：**高** ⭐⭐⭐⭐⭐
- 已有 `account_set_id` 隔离 + 多账套；只需加"批量导入/批量制证/批量预填申报/跨客户台账"。
- 需考虑：一管理员管理多客户、客户间切换、月结批次处理。

## 四、推荐实施路径（三阶段）

### 阶段一：发票归集 + 自动生成凭证（0.5–1.5 个月）
- 新增模块 key `invoice`（发票管理），纳入授权与导航。
- 数据层：`invoice`（主）+ `invoice_line`（明细）表；`account_set↔纳税人` 绑定表；异常队列表。
- 导入通道：Excel/数电 OFD/PDF/OCR/第三方接口（可配置）。优先文件导入（零资质、最快见效）。
- 制证：复用 `genVoucherHandler`，按发票自动生成凭证草稿（借存货+进项/贷应付；借应收/贷收入+销项）。
- 配套：税号→往来单位匹配、税收编码→科目映射、红冲/作废/重复票规则。
- **交付**：代理记账公司把客户发票批量导入，一键生成凭证。

### 阶段二：纳税申报表自动出数（0.5–1 个月）
- 新增模块 key `tax`（报税）。
- 基于 `reportTemplateExecutor` 定义增值税/附加税/企业所得税（预缴）/印花税等申报表模板，自动取数。
- 输出：申报表预览 + 导出 Excel/PDF + 勾稽校验（与财务报表一致）。
- **交付**：会计人工在电子税务局按预填数据申报（半自动）。

### 阶段三：第三方报税对接 + 销项开票（1–2 个月，可选）
- 对接一家第三方财税 SaaS（建议选支持代账多户、覆盖客户所在省份的，如百望云/用友/云账房）。
- 销项：订单/出库 → 自动开数电票 → 回写应收。
- 报税：批量申报推送（需逐客户授权与凭证管理）。
- **交付**：真正"一键报税"。

> 若客户体量大、涉税要求高，也可评估**乐企直连**（仅少数大客户走），但需单独资质与开发。

## 五、风险与合规提示

1. **报税责任重大**：申报数据错误责任在代账公司。务必"先草稿/预览、人工确认后提交"，保留审计留痕。
2. **发票真实性**：进项发票需验真、查重，作废/红冲需处理口径明确。
3. **数据出域**：接第三方云服务时，客户发票/财务数据出本地，需客户书面授权并评估合规。
4. **政策多变**：数电票、申报规则、各省电子税务局持续变化，第三方接口升级需持续适配。
5. **授权与计费**：新增 `invoice`/`tax` 模块 key 纳入注册码体系，便于按模块销售。

---

## 六、结论

- **发票→凭证自动生成：强烈建议做**，系统基础已具备，收益最直接，可最快落地。
- **申报表自动出数 + 人工确认提交：建议做**，作为当前"报税"的稳妥形态。
- **真正一键报税（自动提交）：可行但依赖第三方，属增值阶段**，需评估客户授权与服务费，不建议自研直连电子税务局。
- **总体**：对代理记账公司，本系统凭借"多账套 + 凭证引擎 + 报表取数引擎"，做**发票自动制证与申报出数**是低风险高收益的；做**全自动报税**需借第三方 SaaS 且渐进推进。
