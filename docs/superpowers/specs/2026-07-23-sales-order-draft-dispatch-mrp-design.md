# 销售出库草稿不阻塞 MRP 设计

## 目标

已审核销售订单下推生成销售出库草稿后，仍允许生成 MRP 计算单。销售出库草稿只占用再次出库额度，不代表需求已经履行。

## 业务规则

- 销售出库草稿：占用销售出库下推额度，防止重复生成或超量出库。
- 销售出库已审核：视为销售需求已经履行，扣减销售订单可进入 MRP 的需求量。
- 已审核销售出库发生已审核销售退货时，沿用现有净额计算规则恢复相应需求。
- 已存在有效 MRP 计算单时，继续打开原 MRP，不重复生成。
- 当前库存足以覆盖剩余需求时，仍按现有规则提示无需进入 MRP。

## 技术方案

保留 `scmPushOptions.salesAvailability` 的原始 `pushed_qty`，继续用于销售出库入口状态。新增仅统计已审核销售出库的 `mrp_pushed_qty`，单独计算 MRP 缺口。

`scmMrpDocument.normalizeSalesOrder` 同步只扣减已审核销售出库，确保来源候选、菜单状态和实际创建 MRP 使用相同口径。

## 测试

- 销售订单存在全量销售出库草稿时：销售出库入口显示已有草稿，MRP 仍为可生成，剩余需求保持原订单数量。
- 将同一销售出库改为已审核后：MRP 剩余需求按审核数量扣减。
- 回归销售订单库存缺口、部分发货、已有 MRP、MRP 生命周期及销售订单可用量测试。

## 影响范围

仅修改后端 MRP 来源需求与统一下推菜单计算。无数据库结构变化，无数据迁移。
