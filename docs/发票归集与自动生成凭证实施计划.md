# 发票归集 + 自动生成凭证 · 实施计划（阶段一）

> 项目：CW Finance（财务记账系统）
> 范围：代理记账公司场景下的「发票归集 → 匹配 → 自动生成凭证」
> 原则：**只出计划，不动代码**
> 关联文档：`docs/税控发票报税集成可行性分析.md`（总体可行性）

---

## 0. 目标与边界

**目标**：让代账会计把客户发票（进项/销项）导入系统，系统自动匹配往来单位与科目，一键生成凭证草稿，人工确认后过账，并挂发票附件。

**本期不做**：
- 对接税务局申报/一键报税（见阶段二/三）
- 自动开票（销项开票对接，见阶段三）
- 真正直连税控/电子税务局（不推荐自研）

**本期要做**：
- 独立「发票管理」模块（进项/销项发票归集）
- 数据导入（Excel/CSV 优先，预留数电/接口）
- 映射规则引擎（税号→往来单位、项目/编码/税率→科目）
- 自动生成凭证（草稿）+ 反删回写 + 附件归档

## 1. 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **独立「发票」模块，不复用 scm_doc 的 RP/RS** | 代账客户多数未购进销存(scm)；发票是纯财务维度；费用类发票无物品明细；scm 的"审核→往来台账→制证"流程与代账"归集→匹配→草稿→确认"不同 |
| D2 | **复用凭证写入模式**（参照 `scmDoc.ts:3455` `genVoucherHandler`） | 已有成熟的"按科目汇总→校验借贷平衡→写 vouchers+voucher_entries→回写 source"逻辑 |
| D3 | **生成「草稿凭证」，人工确认后过账** | 报税责任重大，先草稿后过账；凭证 status 已支持 draft/audited/posted |
| D4 | **进项/销项分开处理** | 进项：借成本/费用+进项税 / 贷应付；销项：借应收 / 贷收入+销项税 |
| D5 | **映射规则可配置 + 多级回退** | 税号>往来单位；编码/关键词/税率>科目；最后走默认模板；未命中进异常队列 |
| D6 | **本公司税号取 `account_sets.credit_code`**（统一社会信用代码） | 已有该字段，无需新建 |

## 3. 映射规则引擎（核心）

### 3.1 匹配优先级（从高到低）
1. **对方税号 → 往来单位**：`other_tax_no` 匹配 `scm_partner.tax_no`，取其 `ar_account`/`ap_account`；未命中走辅助核算/默认科目。
2. **明细匹配**：
   - 有 `tax_code`/商品名 → `invoice_rule`（tax_code / keyword 命中）→ 取 `debit_account`/`income_account`；
   - 若商品在 `scm_item` 存在 → 用 `scm_item.inv_account`（存货）/`sale_account`（收入）；
3. **税率 → 进项/销项税科目**：专票且可抵 → `scm:acc_tax_input`；销项 → `scm:acc_tax_output`。
4. **默认模板**（按发票类型）：
   - 进项专票(商品)：借 存货(1405) + 借 进项税 / 贷 应付
   - 进项专票(费用)：借 费用(按规则) + 借 进项税 / 贷 应付
   - 进项普票/数电普票：借 成本/费用(价税合计) / 贷 应付（不可抵）
   - 销项：借 应收 / 贷 收入(6001) + 贷 销项税
5. **未命中** → 状态置 `exception`，进异常队列，不生成凭证。

### 3.2 摘要规则
`${invoice_no} ${other_name} ${item_name/项目}`（与现有 `scmDoc.ts` 摘要风格一致）

### 3.3 价税分离与红冲
- 专票（可抵）：本金入成本/费用，税额入进项税。
- 普票（不可抵）：价税合计入成本/费用。
- 红字发票（`verify_status='red'` / 税额为负）：生成红字凭证（金额取负）。

## 4. 典型凭证分录模板

| 场景 | 借方 | 贷方 |
|---|---|---|
| 进项专票·采购商品 | 库存商品/原材料（不含税）<br>应交税费-进项税（税额） | 应付账款-供应商（价税合计） |
| 进项专票·费用 | 管理费用/销售费用（不含税）<br>应交税费-进项税（税额） | 应付账款（价税合计） |
| 进项普票 | 成本/费用（价税合计） | 应付账款（价税合计） |
| 销项专票/普票 | 应收账款-客户（价税合计） | 主营业务收入（不含税）<br>应交税费-销项税（税额） |
| 红冲 | 反向（取负） | 反向（取负） |

> 收付款不在此阶段自动生成：发票制证挂应收/应付，由出纳/银行流水核销（系统已有往来核销）。

## 5. API 设计

### 发票
- `POST /invoice/import` — 上传 Excel/CSV → 解析入库（返回导入统计+异常清单）
- `GET /invoice/list` — 列表（筛选：direction/status/期间/税号/对方名称）
- `GET /invoice/:id` — 详情 + 明细 + 匹配结果
- `POST /invoice/:id/match` — 触发/重新匹配
- `POST /invoice/batch-match` — 批量匹配（按期间/状态）
- `POST /invoice/:id/generate-voucher` — 单张生成凭证草稿
- `POST /invoice/batch-generate` — 批量生成（预览确认）
- `POST /invoice/:id/void` — 作废/标记红冲
- `POST /invoice/:id/unlink-voucher` — 删除凭证并回写（反生成）
- `GET /invoice/exception` — 异常队列

### 映射规则
- `GET /invoice/rule`、`POST /invoice/rule`、`PUT /invoice/rule/:id`、`DELETE /invoice/rule/:id`

### 数据源（预留，M4）
- `POST /invoice/import/verify` — 验真（可选第三方）
- `POST /invoice/sync` — 数电/第三方接口同步

## 8. 分阶段里程碑与验收

### M1 · 数据模型 + 基础列表（约 1–2 周）
- migration：`invoice` / `invoice_line` / `invoice_rule`
- 后端：CRUD、列表/详情 API
- 前端：`InvoiceList` / `InvoiceDetail`
- **验收**：可手动录入/导入一张发票并查看明细。

### M2 · Excel/CSV 导入 + 查重 + 异常（约 1–2 周）
- 解析管线（进项/销项模板，参照 `cashierImport`/`acdImport` 管线）
- 查重（`invoice_code+invoice_no+direction`）、红冲识别、必填校验
- 异常队列
- 前端：`InvoiceImport` / `InvoiceException`
- **验收**：批量导入 100 张，查重与异常归类正确。

### M3 · 映射规则 + 自动生成凭证（约 2–3 周）
- 税号→往来单位匹配、规则表 + 默认模板、编码/关键词/税率匹配
- 生成凭证草稿（复用 `genVoucherHandler` 模式）、借贷平衡校验、反删回写
- 前端：`InvoiceRule` / `InvoiceGenerate`（预览+差异高亮）
- **验收**：导入→匹配→一键生成凭证草稿→人工过账，借贷平衡；红冲/普票/专票各场景正确。

### M4 · 数据源对接（约 2–3 周，可选）
- 数电票 OFD/PDF/XML 解析、勾选平台导出导入
- 第三方接口与验真（可配置，预留 `invoice/sync`）
- **验收**：对接一种真实数据源（建议先做数电票 OFD/PDF 解析）。

### M5 · 批量与交付（约 1–2 周）
- 跨客户批量处理、月结批次、附件归档（发票原件挂 `voucher_attachments`）、导出
- **验收**：代账会计"月初归集上月发票"场景跑通。

## 10. 风险与依赖

1. **往来单位口径**：代账客户可能用辅助核算（`aux_items`）而非 `scm_partner`。匹配对象需支持两者，阶段一以 `scm_partner.tax_no` 为主、辅助核算兜底；否则未命中进异常队列由会计人工指定。
2. **科目映射准确性**：税收分类编码→科目是最大错误源。务必"先草稿+预览+差异高亮"，不直接过账。
3. **红冲/作废/重复票**：唯一约束与放行策略需谨慎，避免真票被误判重复。
4. **数据源多变**：数电票格式、各省平台导出模板不同，导入解析需可配置模板。
5. **授权计费**：新增 `invoice` 模块 key，纳入注册码 v2 `mods`，需同步两处模块表。
6. **附件合规**：发票原件留存 ≥ 5 年，导入时保存原件并关联凭证。
