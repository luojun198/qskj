# 总账模块评审 + ACD 兼容性 Bug 与优化报告

- **日期**：2026-09-11
- **范围**：总账引擎（`ledgerQuery.ts` / `routes/ledger.ts`）、总账各前端页面、ACD（润衡 `.acd`）导入对总账口径的兼容性
- **方法**：源码走查 + 关键路径交叉验证（含 `npm run build` 类型检查）+ 抽样数据核对；每条均附 `file:line`
- **结论**：总账 `/general`、序时账、外币/数量表已统一走 `voucher_entries` 实时聚合，口径较新且正确；主要问题集中在 **① `/balance` 仍读 `account_balances` 且 FIX-105 参数未接入（并导致编译错误）**、**② 跨年账前发生额漏算**、**③ 年结丢外币/数量期初**、**④ ACD 导入的科目/数量/辅助期初映射缺失，且存在“一张凭证导致整账套导入失败”的致命风险**、**⑤ 前端余额表/日记账的负数、分页、跨年等展示性错误**。

## 三、优化建议（非 Bug）

1. **统一账簿真值源**：`/balance` 改为与 `/general` 一致，基于 `voucher_entries` 动态计算（或提供 `/ledger/rebuild-balances` 对账端点 + 前端“重算余额”按钮），消除 `account_balances` 漂移。
2. **统一 `include_unposted` 语义**：抽一个 `parseBool((raw))` 支持 `'true'|'1'`，所有账簿端点统一支持；余额表补该参数。
3. **分页策略下沉**：明细/日记/序时账的“月/年小计”应由后端按区间聚合返回，或前端在**全量拉取**后计算；避免在服务端分页数据上做小计。
4. **运行余额改服务端**：`/cash-journal` 传 `offset` 后应基于前 N 条累计，返回 `pageStartBalance`（AuxDetail 已这么做），前端不再自算。
5. **金额统一金额分为单位**：`account_balances`/`init_balances` 增加并启用 `*_cents` 列，或至少统一 `moneyRound` + `MONEY_EPSILON` 比较，避免 REAL 尾差。
6. **ACD 导入健壮化**：缺科目时**自动补建占位科目或跳过并计入 warning**（不中断整批）；补 `is_enabled/is_quantity/单位`；辅助期初键改用 `buildAuxItemId` 同源；CLI 与 App 路径合并复用同一套 `applyAccountCodeConfigToDb`。
7. **前端可达性**：恢复 `hideZero` / `showAdvancedFilter` / `Detail.include_unposted` 开关；清理未绑定函数与死代码；统一“变更即查询”。
8. **年结补全**：`writeNextYearInitBalances` 增加 `foreign_*`/`qty_*`/`aux_*` 结转，`pre_book` 按口径处理。
9. **`/balance` 接 `preBook`**：补类型声明与路由参数（`accountSetStartDate`、`preBookEnabled`），修复编译错误（GL-01）。
