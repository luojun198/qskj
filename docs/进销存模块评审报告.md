# 进销存（SCM）模块评审报告

> 评审时间：2026-09-05
> 范围：单据全生命周期（创建/审核/反审核/删除/生成凭证）、库存成本、往来收付、批次/序列号、生产/委外联动
> 基线：SCM 相关 222 个单测全部通过（18 个测试文件，含生产/委外全链路 41 用例）
> 结论：**核心引擎健壮（成本/审核/反审核/核销/生产三阶段逻辑严密）；但发票单据（RP/RS）是半成品、往来与凭证存在税额口径矛盾、整单折扣不传导，这三项建议优先处理。**

---

## 一、高优先级

### 🔴 S1 · RP/RS 发票单据是「半成品」：不挂往来、生成不了凭证、行金额可能丢失
- 证据链：
  - 单据类型配置 `ar_ap: 1`（`scmDoc.ts:201-202`）；
  - `scmArAp.ts:5` 头注释「审核采购/销售发票（RP/RS）审核时：生成应收应付分录」，`applyInvoice`（`scmArAp.ts:77`）已实现，但**全库无任何调用**（死代码）；
  - 审核链路（`scmDoc.ts:1576-1594`）对 RP/RS：`stock=0` 无库存移动、无往来挂账，仅状态流转；
  - `genVoucherHandler`（`scmDoc.ts:3502-3586`）：RP/RS `cat=purchase/sale` 但 `dir='none'`，purchase/sale 分支只处理 `dir in/out` → **不产生任何分录**，报「无有效分录」；
  - `buildDocLineRow`（`scmDoc.ts:314-318`）落库金额恒等于 `qty×price×行折扣`，**忽略前端传入的 amount** —— 发票只填金额不填数量时金额直接丢成 0。
- 影响：发票登记功能名存实亡（只能查、不能挂账、不能制证）。
- 建议：与《发票归集与自动生成凭证实施计划》合并决策——**推荐按独立「发票管理」模块重做**（发票数据模型 + 制证），RP/RS 保留为进销存内的发票登记或废弃；若保留则需补 `applyInvoice` 接线 + genVoucher 的 RP/RS 分录模板 + 行金额直录支持。

### 🔴 S2 · 往来台账（不含税）与凭证应收/应付（含税）口径矛盾
- 证据链：
  - SO 审核挂应收 = Σ行金额**不含税**（`scmArAp.ts:94-108`，注释明示「无税」；测试 `scmInventoryArap.test.ts:116` 断言不含税）；
  - 凭证借应收 = amt + tax **含税**（`scmDoc.ts:3534`）；PI/应付同理（`scmDoc.ts:3529`）。
- 后果（可复现）：
  1. 总账应收/应付科目余额 ≠ 往来余额表/账龄/对账单（差一个税额）；
  2. 收付款按含税额录入时，核销 in-log（不含税）核不平——税额部分永远留在「未核销收款/付款」，污染预收预付统计（`verifyArAp` 越界拦截 `scmArAp.ts:447`）。
- 建议：统一口径。推荐**往来台账也按含税挂账**（核销才闭环、报表与总账一致）；若坚持「发货不含税 + 开票含税」两段式，则必须把 S1 的发票挂账补上，形成「发货暂估 → 开票冲销 → 发票挂账」闭环。

### 🔴 S3 · 整单折扣只改表头合计，不传导到凭证/往来
- 证据链：
  - 行金额 = `qty×price×`**行折扣**（`buildDocLineRow`，`scmDoc.ts:314-318`）；
  - 表头 `total_amount` = Σ行金额 × **整单折扣**（`scmDoc.ts:967/1037`）；
  - 凭证（genVoucherHandler 按行汇总）、应收/应付（applyReceivableFromShipment/applyPayableFromReceipt 按行）**都不知道整单折扣**。
- 后果：用了整单折扣的单据，单据列表合计 ≠ 凭证金额 ≠ 往来挂账额。
- 建议：保存时把整单折扣按比例分摊到行（同步行折扣额/税额），行折扣口径保持不变；或凭证/往来统一取表头合计。

## 二、中优先级

### 🟠 S4 · 取号无并发保护，并发保存会 500
- `nextDocNo` / `nextSeqNo`（`scmDoc.ts:3757-3764`）为「查最大+1」，无锁无重试；并发创建撞 `UNIQUE(account_set_id, doc_type, doc_no)` 直接抛约束错误。
- 建议：INSERT 冲突时自动重试取号（最多 3 次），或仿凭证录入的 `BEGIN IMMEDIATE` 包住取号+插入。

### 🟠 S5 · 负库存出库成本取 0
- `applyMovingAvgOut`（`scmCosting.ts:70-93`）：无库存记录时 `unitCost=0` → 销售出库结转成本 0、库存金额 0，低估成本。
- 建议：负库存放行时返回提示（creditWarning 机制已有，可复用）；或按物料最近进价兜底。

### 🟠 S6 · 盘点（CK）不维护序列号
- `scmSerial.ts:72`：`dir==='none'` 直接 return（注释已声明「盘点暂不处理」）。启用序列号的物料盘盈/盘亏后，序列号台账与库存脱节。
- 建议：至少对盘亏出库做核销、盘盈入库做登记；或审核时给出「该单含序列号物料，序列号台账未更新」警告。

### 🟡 S7 · reverseDocMoves 回算均价未舍入
- `scmCosting.ts:158`：`avg = newAmt/newQty` 未按 4 位舍入，与 `applyMovingAvgIn/Out` 的 1e-4 精度口径不一致，极端情况有尾差。极低风险，顺手统一即可。

## 四、正向确认（无需改动）

- **审核事务原子性**：批次/序列号校验失败整单回滚（`scmDoc.ts:1601-1606`）。
- **反审核安全网完整**：已生成凭证拦截、下游单据/计划/MRP 引用拦截、核销拦截、PF/PS/WI 的完工数/报废数/人工制费吸收精确回退（`scmDoc.ts:1614-1700`）。
- **出库库存预检按 物料+仓库 聚合**，避免同料多行各自过关（`checkAggregatedOutStock`，`scmDoc.ts:1084`）。
- **移动加权成本引擎正确**：入/出/回滚的均价数学成立，回滚前整单负库存预检（`scmCosting.ts`）。
- **收付款核销**：事务 + 双向越界拦截 + 反核销（`scmArAp.ts:422-473`）。
- **生产成本三阶段**：领料归集 → 完工上卷（末批吸收 WIP）→ 人工制费跨批 true-up + 报废只计料，测试 41 用例覆盖（`scmProductionFlow/scmOutsourceFlow`）。
- **计价方式守卫**：未实现的计价方式禁止审核（`scmDoc.ts:1137-1143`）。
