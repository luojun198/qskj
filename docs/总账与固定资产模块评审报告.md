# 总账 / 固定资产 模块评审报告

> 评审时间：2026-09-05
> 范围：总账（凭证/账簿/期间） + 固定资产（卡片/折旧/变动/处置/盘点）
> 基线：后端 GL/资产相关 282 个单测全部通过（18 个测试文件）
> 结论：**总体健壮，凭证核心并发/平衡/结账管控到位；固定资产变动与盘点存在几处可导致账实不符的缺陷，建议优先修复。**

## 一、固定资产模块 · Bug 修复

### 🔴 A1 · 改良(improvement)延长使用月数后，撤销变动未还原 use_months（高）
- 位置：`assetChange.ts:292-339`（applyValueChange 写入）/ `assetChange.ts:922-938`（revokeAssetChange）
- 问题：improvement 会更新 `use_months`，但 `writeChange` 只记录 `old_value/new_value/amount`，未存旧的 use_months；撤销时只还原 `original_value/salvage_value/net_value`，**use_months 残留为延长后的值**。
- 影响：撤销后资产按错误的剩余月数继续折旧，折旧额与账面不一致。
- 修复：improvement 在 change 记录中存入旧 use_months（或独立字段），撤销时一并还原。

### 🔴 A2 · 折旧要素调整「残值率」撤销后 salvage_value 未重算（高）
- 位置：`assetChange.ts:634-639`（改 salvage_rate 重算 salvage_value）/ `assetChange.ts:962-971`（撤销）
- 问题：applyDeprFactorChange 改残值率时同步重算 `salvage_value`；撤销只把 `salvage_rate` 还原，**salvage_value 留在调整后的值**。
- 影响：残值率与残值不一致，后续「剩余期间摊余」折旧算错。
- 修复：撤销 salvage_rate 时同步按还原后的残值率重算 salvage_value。

### 🔴 A3 · 盘亏只记凭证，未更新资产卡片（高）
- 位置：`assetInventory.ts:196-247`（completeInventory）
- 问题：盘亏生成凭证（借盘亏科目/借累计折旧/贷固定资产原值），但 **fixed_asset 卡片未标记报废/处置**（未改 status_code、未置 scrap_date）。
- 影响：盘亏资产仍留在资产卡片且**继续计提折旧**，账实双计、资产账与总账不符。
- 修复：盘亏完成后将对应资产置为处置状态（或记录盘点差异并停止折旧）。

### 🔴 A4 · 盘盈未建资产卡片（高）
- 位置：`assetInventory.ts:335-340`
- 问题：盘盈仅生成凭证，**未创建 fixed_asset 记录**。
- 影响：盘盈入账的资产无法在资产模块管理、也无法计提折旧；与总账不平。
- 修复：盘盈项补建资产卡片（原值=盘盈净值、状态=在用、起折日期按需）。

### 🟠 A5 · 撤销「使用月数」调整可能使 use_months < 已计提月数（中）
- 位置：`assetChange.ts:962-971`
- 问题：撤销 use_months 调整无校验；若期间已发生折旧，可能把 use_months 还原到小于 `depr_months_done`。
- 影响：折旧引擎 `if (depr_months_done >= use_months) return 0` 静默停止计提。
- 修复：撤销时校验还原后的 use_months 必须 > 已计提月数，否则拦截。

### 🟠 A6 · 卡片可直改 scrap_date / scrap_reason / depr_months_done（中）
- 位置：`assetCard.ts:62-86`（UPDATABLE_CARD_FIELDS）
- 问题：`scrap_date/scrap_reason` 可经 PUT /asset/cards/:id 直改，绕过处置流程；`depr_months_done` 可直改破坏折旧序列。
- 影响：数据被手工改乱，折旧/处置逻辑失序。
- 修复：将 `scrap_date/scrap_reason` 从可改字段移除（或仅允许内部写入）；`depr_months_done` 禁止直改。

## 二、固定资产模块 · 优化

### 🟡 A7 · 卡编号自动递增在并发下可能冲突（低）
- 位置：`assetChange.ts:724-738`（nextAutoNo）
- 说明：拆分/新增卡片取「最大编号+1」，单机低并发可接受；高并发下有重复风险，建议用独立序号表或加唯一约束兜底。

### 🟡 A8 · 处置/变动凭证的部门辅助核算仅按「编码优先、名称兜底」匹配（低）
- 位置：`assetVoucherBuilder.ts:106-128`
- 说明：资产部门字典与系统辅助核算部门是两套数据，匹配不到时静默跳过辅助项（不阻断凭证）。可提示用户辅助项未命中，避免辅助明细账缺数。

## 三、总账模块 · 评审结论

### 已确认的健壮点（无需改）
- **并发安全**：凭证录入用 `BEGIN IMMEDIATE` + 3 次重试（`voucher.ts:682-689`）。
- **借贷平衡**：用整数分（cents）判断，无浮点误差（`voucherEntry.ts:180-197`）。
- **状态管控**：已记账凭证禁止删除/反审核；结账期间拒写；制单人与审核人不能同一人。
- **跨年账簿**：期初/期末余额按起止年度分别计算，避免跨年重复（`ledgerQuery.ts:119-128`）。
- **凭证时序**：日期上限=当月最后一天、不得早于账套启用日、可选时序控制（`voucherEntry.ts:130-161`）。

### 🟡 G1 · 凭证日期"当月最后一天"用服务器本地时区判断（低）
- 位置：`voucherEntry.ts:145-150`
- 说明：`new Date()` 取服务器时区，若服务器时区与代账公司不一致，月末/跨日边界可能偏差一天。建议按账套/前端时区计算或统一 UTC+8。

### 🟡 G2 · 无凭证类型时自动继承上一张类型（低）
- 位置：`voucherEntry.ts:515-526`
- 说明：该期间首张未指定类型的凭证会继承"最近一张"的凭证类型。属设计行为，但用户可能未察觉，建议前端在保存时提示"将归入 XX 类型"。

## 五、建议

1. **优先修复 A1–A4**：这四项会直接导致「资产模块与总账/账实不符」，属于会计正确性问题。
2. **A5–A6** 属于健壮性，建议随修复一起处理（补校验 + 收紧可改字段）。
3. **A7–A8 / G1–G2** 为优化项，可后续迭代。
4. 建议为 A1–A6 各补 1–2 条单测（现有 `assetChange.test.ts` 69 用例、`assetInventory.test.ts` 9 用例可扩展覆盖撤销/盘盈盘亏场景）。
